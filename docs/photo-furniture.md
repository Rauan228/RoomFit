# Моя мебель: 3D по фото

В редакторе: **Мебель → Создать мебель по фото**. Загрузи основной ракурс и, по возможности, задний/боковые ракурсы того же предмета; укажи ширину, глубину и полную высоту. Примерные размеры явно отмечены. Последний шаг требует согласия на передачу фото Tripo и расход кредитов.

Готовая мебель сначала доступна для проверки: вид сверху и изометрический рендер, кнопка вращаемого 3D, изменение размеров/направления без повторной AI-генерации. После подтверждения предмет попадает в существующий личный каталог. «Добавить в текущую комнату» использует обычные undo, автосохранение, 2D/3D, экспорт и общий доступ к комнате.

## Запуск

Настройки только в `api/.env` (см. `.env.example`). Ключ не отправляется в браузер. В отдельных терминалах:

```powershell
npm run dev:platform
# из api/, с активированным venv:
python -m uvicorn roomfit.app:app --host 127.0.0.1 --port 4182
python -m roomfit.photo_jobs
```

Нужен Blender: `ROOMFIT_BLENDER` — абсолютный путь к исполняемому файлу. На компьютере проверен Blender 4.5.14. Для старого CPU VPS без SSE4.2 предусмотрен совместимый импорт в Blender 3.6.23; его рендер использует Filmic без OIDN. На современном CPU предпочтителен актуальный Blender. Размеры и ориентация проверяются независимо от выбранного рендера.

```dotenv
TRIPO_API_KEY=...
TRIPO_ENABLED=true
TRIPO_MODEL_VERSION=v3.1-20260211
TRIPO_DAILY_CREDIT_LIMIT=40
TRIPO_TOTAL_CREDIT_LIMIT=40
TRIPO_USER_DAILY_LIMIT=1
TRIPO_MAX_CONCURRENT_JOBS=1
TRIPO_JOB_CREDIT_RESERVE=40
ROOMFIT_BLENDER=/absolute/path/to/blender
ROOMFIT_PHOTO_STORAGE=data/photo-furniture
ROOMFIT_PHOTO_USER_STORAGE_MB=500
```

Общий лимит действует на всю историю; `0` отключает только общий лимит. Суточный лимит `0` отключает новые генерации. Резерв — 40 кредитов на H-series со стандартной геометрией и подробной текстурой, фактический расход берётся из ответа провайдера. Повторно платная задача автоматически не отправляется даже после потери ответа. Для следующих генераций владелец должен явно расширить бюджет.

На VPS проведены четыре реальные генерации: стул из двух фото, шкаф, тумба с зеркалом и стол — по **40 кредитов**, всего **160**. После отдельного согласия на три оставшиеся модели общий и суточный лимиты установлены в `160`, пользовательский — в `4`; весь разрешённый бюджет использован. Пример выше сохраняет меньший стартовый бюджет для новой установки. Шкаф и тумба показали ограничения реконструкции зеркал: отражённая комната и мелкие вещи могут превратиться в лишнюю геометрию или остаться в текстуре. Успешная техническая проверка не означает точное визуальное восстановление; результаты нужно просматривать перед использованием.

## Устройство и ограничения

- FastAPI использует существующие сессии, CSRF и `personal_furniture`. Добавлены только таблицы очереди, блокировки и учёта расходов; миграция `20261015_photo_furniture` сохраняет проекты и пользователей.
- Очередь в PostgreSQL/SQLite переживает перезапуск, хранит `task_id`, этап, срок, lease и версии. Отдельный worker выполняет HTTP и Blender; API-запрос не ждёт рендера. GET/скачивание повторяются с задержкой; неопределённый результат платного POST требует ручной сверки с Tripo.
- PNG/JPEG/WebP ≤8 МБ, 256 пикселей минимум, ≤24 Мп. EXIF удаляется, поворот учитывается, отправляется PNG ≤2048 px. Оригинал хранится отдельно; обрезка не перезаписывает его. 1–4 фото: основной front обязателен. Сложный фон, зеркала и закрытые предметами части ухудшают реконструкцию; текстовое описание сохраняется, но не передаётся как несуществующий API-параметр.
- Оригинальный GLB скачивается в постоянное приватное хранилище. Проверяются HTTPS, точные CDN-хосты, публичный IP, размер и структура GLB; Authorization не передаётся в CDN. Подписанный URL Tripo не становится адресом модели в проекте.
- Blender приводит модель к размерам, нижнему центральному pivot и осям RoomFit. Текстуры/материалы сохраняются, карты уменьшаются до 1024 px. Нормализация по осям может менять пропорции; при заметном изменении показано предупреждение. Реальная точность формы по фотографиям не гарантируется.
- 2D PNG/WebP, технический SVG, контуры и высотные объёмы получаются из того же GLB. Независимая проверка: габариты/pivot ≤1 мм, совпадение силуэта ≥97%, проверка направления по координатному рендеру. До 60 тыс. треугольников и 12 МБ. Высотные collision bands консервативны, это не точная физическая модель.
- В проекте закрепляется версия с проверенной геометрией и хешем. Произвольные URL, подмена геометрии и ссылки на чужие предметы отклоняются сервером. Обновление личной мебели не меняет уже сохранённые комнаты.
- Файлы выдаются только владельцу либо по действующей ссылке на комнату, в которой присутствует подтверждённая версия. Фото по share-ссылке не выдаются. Отзыв ссылки сразу закрывает доступ. Удаление предмета из каталога сохраняет файлы для старых комнат; удаление аккаунта удаляет его файлы, но не обнуляет журнал расходов.
- Лимиты: 10 неархивных черновиков, 20 версий одного предмета, 500 МБ личных данных по умолчанию. Архивирование сохраняет версии, поэтому освобождение диска требует проверки ссылок владельцем сервиса.

## Проверки без расхода кредитов

```powershell
npm test
npm run test:api
npm run build --workspace @roomfit/platform
npx playwright test --config playwright.photo.config.ts
```

Браузерные тесты поднимают отдельные API 4192 и preview 4193 с изолированной тестовой БД. Tripo заменён локальным provider fixture, результат помечен как тестовый и не выдаётся за AI-генерацию. API-ключ принудительно заменяется фиктивным. Реальный GLB отдельно проверен настоящим Blender.

## VPS

После проверок: `scripts/deploy-photo-furniture.ps1`, затем `scripts/deploy-web.ps1`. Первый обновляет строго перечисленные API-файлы с SHA256, резервной копией и откатом кода, применяет добавочную миграцию и устанавливает `roomfit-photo-worker.service`; существующие `.env`, PostgreSQL и каталог другой мебели не заменяются. Передай ключ отдельно в защищённый `api/.env`, без командной строки/репозитория, укажи Blender и бюджет. Worker: пользователь roomfit, Nice 10, CPUQuota 100%, MemoryMax 2G, запись только в `api/data`.

Хранилище — `/opt/roomfit/api/data/photo-furniture`, вне веб-релизов. `deploy/backup.sh` сохраняет PostgreSQL, защищённое окружение и это хранилище. Восстанавливать нужно согласованную БД и соответствующие файлы версий. Логи: `journalctl -u roomfit-photo-worker`, приватные `processing.log` внутри версии. Не публикуй исходные фото, подписанные URL или `.env` вместе с диагностикой.

Контракт и цены сверены 15.10.2026 с [официальной документацией H-series](https://developers.tripo3d.ai/en/docs/generation-multiview-to-model/standard) и [тарифами Tripo](https://developers.tripo3d.ai/en/pricing).
