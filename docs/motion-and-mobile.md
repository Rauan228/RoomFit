# Динамика и мобильный первый экран

Применён скилл [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill), установленный из `.claude/skills/ui-ux-pro-max` в `D:/VisualMind/VisualMind/.codex/skills/ui-ux-pro-max`. Ранее доступная копия в `.agents/skills` сохранена.

Запросы к установленной базе: `Hero-Centric Design` (landing), `reduced motion animation` (ux), `scroll reveal stagger` (gsap), `cleanup effects` (react). Дополнительно прочитаны рекомендации по типографике, мобильным размерам и анимациям из `references/quick-reference.md`.

Применённая композиция: один основной CTA, компактный заголовок, читаемый контраст поверх фотографии и крупный план вместо уменьшенного десктопного интерфейса. На ширине до 700 px каталог и боковая панель декоративного превью скрываются; сам интерактивный редактор ниже сохраняет каталог и свои действия. В мобильном hero остаются три коротких преимущества. Каталог в рабочем демо получил поле поиска с размером шрифта 16 px и более удобные размеры элементов.

Анимации реализованы средствами браузера, без новой зависимости: Web Animations API, IntersectionObserver и CSS. При прокрутке секции появляются один раз, карточки — с небольшим сдвигом по времени. Навигация показывает текущий раздел и прогресс просмотра. На устройствах с мышью превью реагирует на положение указателя; нажатия, карточки, FAQ, меню и диалоги имеют собственный отклик.

Контент не скрыт по умолчанию. Анимации не блокируют кнопки и отменяются при взаимодействии с элементом. Обработчики, наблюдатели и кадры очищаются при размонтировании. Смена `prefers-reduced-motion` немедленно отменяет активные эффекты и восстанавливает статическое отображение; декоративных бесконечных циклов нет.

Появление подготавливается в `useLayoutEffect` до первого кадра: анимации ожидающих элементов стоят на паузе в начальном состоянии. Каждый элемент запускается один раз, немного раньше входа в видимую область. Небольшой сдвиг 12 px и переход 720 мс убирают резкий скачок. После завершения эффект снимается, сохраняя обычное видимое состояние; прокрутка обратно не запускает его заново. Браузерный тест проверяет покадровое увеличение прозрачности без скачка из 1 в 0.

Документация: [Web Animations API](https://developer.mozilla.org/en-US/docs/Web/API/Element/animate), [IntersectionObserver](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API), [prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion).
